(이 문서는 에이전트에게 주는 절차서다. 보통 에이전트가 문서 작업 중에 스스로 따른다.)

한글 본문을 MCP 쓰기 도구로 보내기 전에 **기준본**을 만든다. 기준본이 있으면 훅이 보낼 값과 문자 단위로 대조해, 재생산 과정에서 글자가 표류한 경우를 사람이 읽지 않고도 잡아낸다.

> ⚠️ **이 커맨드는 파일을 준비할 뿐, 대조는 하지 않는다.** 대조는 전적으로 `PreToolUse` 훅이 한다.
> 훅이 물려 있지 않으면(설치 전에 시작된 세션 등) 기준본만 남고
> **아무것도 검사되지 않는다.** 그 상태에서 「기준본을 만들었으니 기계적으로 확인됐다」고 여기면 안 된다.
>
> 훅 없이 확인하려면 저장한 뒤 서버에서 다시 fetch 해서 기준본과 `diff` 로 대조하라 — 그게 유일한 방법이다.

## 할 일

1. 기준본 폴더를 정한다 — 이 프로젝트의 `.claude/hangul-staging/` (없으면 만든다).
   `HANGUL_STAGING` 환경변수가 설정돼 있으면 그쪽이 우선이다. 아래 두 폴더를 쓴다.

   ```
   current/<문서 id>.md   서버 본문 사본  → 표류 대조 (내가 안 쓴 사본)
   target/<문서 id>.md    내 최종본       → 삭제·누락 판정
   ```

   파일 이름이 곧 대상 문서다 — 노션은 `page_id`, Jira 는 이슈 키(`target/PROJ-123.md`).
   이름이 안 맞으면 그 문서의 기준본으로 인정되지 않아 에코 경로로 떨어진다.
   (하위 호환으로 staging 루트의 `<문서 id>.md` 도 target 으로 인정된다)

2. **기존 문서를 고치는 작업이면 `current/` 를 먼저 채운다.** `notion-fetch` · `getJiraIssue` 로
   받은 서버 본문을 **그대로** `current/<문서 id>.md` 에 쓴다 — 다듬거나 요약하지 않는다.
   이 사본만은 내가 쓰지 않은 것이라, 안 바꾼 줄을 다시 타이핑하다 어긋난 경우를 잡는 유일한 근거다.
   비어 있으면 앵커로 함께 보낸 줄들이 전부 「새 한글」로 걸려 에코가 잦아진다.

3. 보낼 본문 전체를 **Write 도구나 Bash heredoc으로** `target/<문서 id>.md` 에 쓴다.
   ⚠️ MCP 파라미터로 본문을 만들지 말고, 파일 쪽을 먼저 쓴다. 두 사본이 **독립적으로** 작성돼야 대조가 의미를 갖는다.

4. 그다음 노션·Jira 쓰기 도구를 호출한다. 훅이 자동으로 대조한다.

   **가능하면 본문 대신 마커를 보낸다.** 훅이 파일 내용으로 치환하므로 그 글자는 파라미터를
   한 번도 거치지 않는다 — 표류가 원천적으로 불가능해지고 토큰도 준다.

   ```
   "@@hangul:target/PROJ-123.md@@"          파일 전체
   "@@hangul:current/PROJ-123.md#L12@@"     12번째 줄        (old_str 처럼 조각이 필요할 때)
   "@@hangul:current/PROJ-123.md#L12-L15@@" 12~15번째 줄
   ```

   ⚠️ **이스케이프(`\uXXXX`)를 만들어 옮겨 적지 마라.** `json.dumps` 로 생성하면 코드포인트
   계산은 맞지만, 그 결과를 파라미터로 **다시 옮기는 단계**가 남는다. ASCII 16진이라 눈에 안
   보일 뿐 재생산은 그대로이고, 틀려도 유효한 한글로 디코드돼 아무도 못 잡는다.
   기존 본문의 조각이 필요하면 줄 지정 마커를 써라.

## 훅이 막았을 때

- **「기준본과 길이가 같은데 N글자가 다릅니다」** — 표류다. 틀린 위치·문자·코드포인트가 함께 나온다.
  기준본 쪽 문자열을 그대로 보낸다. 의도한 수정이면 기준본을 먼저 고친다.
- **「old_str 이 서버 본문 사본과 다릅니다」** — 앵커가 페이지 원문과 어긋났다.
  `current/` 의 그 줄을 그대로 보내거나, 줄 지정 마커로 보낸다.
- **「본문을 통째로 바꾸는데 기준본의 항목이 빠졌습니다」 / 「old_str 이 삼킨 항목이…」** —
  그대로 보내면 그 항목들이 에러 없이 삭제된다. 되돌려 놓거나, 정말 지울 거면 기준본에서 먼저 지운다.
- **「기준본에 없는 새 한글입니다」** — 대조할 기준이 없어 눈으로 확인받는 경우다.
  읽고 이상 없으면 같은 값을 그대로 다시 보내면 통과한다. 기존 문서를 고치는 중이라면
  `current/` 를 채우라는 안내가 함께 나온다 — 그게 근본 해결이다.
- **「마커가 가리키는 기준본이 오래됐습니다」** — 6시간이 지난 파일이다.
  서버 본문이 바뀌었을 수 있으니 다시 fetch 하거나, 그대로 보낼 것이면 한 번 더 호출한다.

## 작업이 끝나면

기준본은 남겨도 되고 지워도 된다. 다만 **오래된 기준본이 남아 있으면** 새 문자열이 매칭되지 않아 에코 경로로 떨어지므로, 문서를 크게 바꿨으면 갱신한다.
