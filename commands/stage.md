---

(이 문서는 에이전트에게 주는 절차서다. 보통 에이전트가 문서 작업 중에 스스로 따른다.)

한글 본문을 MCP 쓰기 도구로 보내기 전에 **기준본**을 만든다. 기준본이 있으면 훅이 보낼 값과 문자 단위로 대조해, 재생산 과정에서 글자가 표류한 경우를 사람이 읽지 않고도 잡아낸다.

> ⚠️ **이 커맨드는 파일을 준비할 뿐, 대조는 하지 않는다.** 대조는 전적으로 `PreToolUse` 훅이 한다.
> 훅이 물려 있지 않으면(설치 전에 시작된 세션 등) 기준본만 남고
> **아무것도 검사되지 않는다.** 그 상태에서 「기준본을 만들었으니 기계적으로 확인됐다」고 여기면 안 된다.
>
> 훅 없이 확인하려면 저장한 뒤 서버에서 다시 fetch 해서 기준본과 `diff` 로 대조하라 — 그게 유일한 방법이다.

## 할 일

1. 기준본 폴더를 정한다 — 이 프로젝트의 `.claude/hangul-staging/` (없으면 만든다).
   `HANGUL_STAGING` 환경변수가 설정돼 있으면 **그 폴더 하나만** 쓴다 — 폴백이 아니라
   배타적 지정이라 프로젝트 폴더는 후보에서 빠진다. 아래 두 폴더를 쓴다.

   ```
   current/<문서 id>.md   서버 본문 사본  → 표류 대조 (내가 안 쓴 사본)
   target/<문서 id>.md    내 최종본       → 삭제·누락 판정
   ```

   **새로 만들 때는 `.gitignore` 를 같이 넣는다** — 기준본은 서버 본문 사본이라 저장소에 올릴
   것이 아니다. 폴더 안에 두면 프로젝트의 `.gitignore` 를 건드리지 않는다.

   ```bash
   mkdir -p .claude/hangul-staging/{current,target}
   printf '*\n' > .claude/hangul-staging/.gitignore
   ```

   (빠뜨려도 훅이 다음 MCP 호출에서 스스로 놓는다 — 단 git 워크트리 안이고, 폴더가 이미 있고,
   그 폴더에 추적 중인 파일이 없을 때만이다. 이미 있는 파일은 덮어쓰지 않는다.
   추적 중이라 못 넣었으면 세션에 한 번 그 사실을 알려준다.)

   ⚠️ **staging 폴더는 검색 도구에 안 잡힌다.** `.claude` 가 숨김 디렉토리라 무시 설정과
   무관하게 기본 `rg` 에는 원래 안 잡히고, `.gitignore` 가 `rg --hidden` 까지 막는다.
   줄 번호는 **파일 경로를 직접 줘서** 센다 —
   `grep -n '<패턴>' .claude/hangul-staging/current/<문서 id>.md` 는 정상이다.
   ⚠️ 재귀 탐색(`grep -rn .claude/…`)은 빈 결과가 나올 수 있다(ugrep 등은 숨김 폴더를 건너뛴다).
   목록이 필요하면 `ls` 나 `rg --hidden --no-ignore` 를 쓴다.

   경로는 **절대경로로 쓰거나 프로젝트 루트에서** 만든다. 훅은 셸의 현재 작업 디렉토리에서
   **가장 바깥 저장소 루트까지** 올라가며 찾으므로 하위 폴더·서브모듈 안에 있어도 된다.
   다만 저장소 **밖**(`.git` 없음)에서는 올라가지 않고, 남이 쓸 수 있는 폴더는 건너뛴다.

   파일 이름이 곧 대상 문서다 — 노션은 `page_id`, Jira 는 이슈 키(`target/PROJ-123.md`).
   이름이 안 맞으면 그 문서의 기준본으로 인정되지 않아 에코 경로로 떨어진다.
   (하위 호환으로 staging 루트의 `<문서 id>.md` 도 target 으로 인정된다)

2. **기존 문서를 고치는 작업이면 `current/` 를 먼저 채운다.** `notion-fetch` · `getJiraIssue` 로
   받은 서버 본문을 **그대로** `current/<문서 id>.md` 에 쓴다 — 다듬거나 요약하지 않는다.
   이 사본만은 내가 쓰지 않은 것이라, 안 바꾼 줄을 다시 타이핑하다 어긋난 경우를 잡는 유일한 근거다.
   비어 있으면 앵커로 함께 보낸 줄들이 전부 「새 한글」로 걸려 에코가 잦아진다.

3. 보낼 본문 전체를 **Write 도구나 Bash heredoc으로** `target/<문서 id>.md` 에 쓴다.
   ⚠️ MCP 파라미터로 본문을 만들지 말고, 파일 쪽을 먼저 쓴다. 두 사본이 **독립적으로** 작성돼야 대조가 의미를 갖는다.

4. 그다음 노션·Jira 쓰기 도구를 호출한다. 훅이 자동으로 대조한다.

   **가능하면 본문 대신 마커를 보낸다.** 훅이 파일 내용으로 치환하므로 그 글자는 파라미터를
   한 번도 거치지 않는다 — 표류가 원천적으로 불가능해지고 토큰도 준다.

   ```
   "@@hangul:target/PROJ-123.md@@"          파일 전체
   "@@hangul:current/PROJ-123.md#L12@@"     12번째 줄        (old_str 처럼 조각이 필요할 때)
   "@@hangul:current/PROJ-123.md#L12-L15@@" 12~15번째 줄
   ```

   **마커를 쓸 수 있으면 조각내지 말고 통짜로 보낸다.** 「긴 `old_str` 은 쪼개라」는 한글을
   파라미터에 실을 때의 규칙이다. 마커는 재생산이 0 회라 길이가 무의미하고, 왕복도 줄고,
   조용한 삭제도 배치 단위로 한눈에 검토된다 (실측: `old_str` 73줄 · `new_str` 131줄을 포함한
   섹션 5개 배치가 한 번에 통과했다).

   마커는 문자열 **전체**가 그 형태일 때만 치환된다. 앞뒤에 다른 글자가 붙거나 `#L12-15` ·
   `#12` 처럼 형태가 어긋나면 치환되지 않는다(훅이 차단한다).
   줄 번호는 1 부터이고 끝 줄을 포함한다 — **`grep -n` 으로 확인하고 적어라.** 범위 안에서
   잘못 센 줄 번호는 훅이 잡지 못한다(그 줄도 기준본에 실재하는 줄이라 전부 통과한다).
   본문을 통째로 갈아끼우는 자리(`fields.description` · `body` · `replace_content` 의 `new_str`)에는
   줄 지정 마커를 쓰지 마라 — 지정한 줄만 남고 나머지가 삭제된다(훅이 차단한다).
   훅이 물려 있지 않으면 마커 문자열이 그대로 저장된다. 훅이 없는 세션에서는 리터럴 UTF-8 로 쓴다.

   ⚠️ **이스케이프(`\uXXXX`)를 만들어 옮겨 적지 마라.** `json.dumps` 로 생성하면 코드포인트
   계산은 맞지만, 그 결과를 파라미터로 **다시 옮기는 단계**가 남고 분량도 리터럴의 약 4배다.
   (훅은 디코드된 값을 보므로 이스케이프로 보낸다고 검사를 피하지는 못한다 — 대조는 똑같이 돈다.)
   `json.dumps` 를 부를 수 있다는 것은 본문이 이미 파일에 있다는 뜻이다. 그 파일을 staging 에
   두고 마커로 가리켜라. 기존 본문의 조각이 필요하면 줄 지정 마커를 쓰고, 마커를 쓸 수 없는
   자리면 리터럴 UTF-8 로 쓴다.

## 훅이 막았을 때

- **「기준본과 길이가 같은데 N글자가 다릅니다」** — 표류다. 틀린 위치·문자·코드포인트가 함께 나온다.
  이 값 전체가 기준본의 한 구간과 같아질 수 있으면 옮겨 적지 말고 그 구간을 마커로 보낸다.
  그렇지 않으면 기준본 쪽 문자열을 그대로 보낸다. 의도한 수정이면 기준본을 먼저 고친다.
- **「old_str 이 서버 본문 사본과 다릅니다」** — 앵커가 페이지 원문과 어긋났다.
  `current/` 의 그 줄을 그대로 보내거나, 줄 지정 마커로 보낸다.
- **「본문을 통째로 바꾸는데 기준본의 항목이 빠졌습니다」 / 「old_str 이 삼킨 항목이…」** —
  그대로 보내면 그 항목들이 에러 없이 삭제된다. 되돌려 놓거나, 정말 지울 거면 기준본에서 먼저 지운다.
- **「기준본에 없는 새 한글입니다」** — 대조할 기준이 없어 눈으로 확인받는 경우다.
  읽고 이상 없으면 같은 값을 그대로 다시 보내면 통과한다. 다만 그 재전송도 재생산이다 —
  본문을 staging 파일로 쓰고 마커로 보내면 재생산이 0 회가 된다.
  기존 문서를 고치는 중이라면 `current/` 를 채우라는 안내가 함께 나온다 — 그게 근본 해결이다.
- **「치환되지 않은 마커가 남아 있습니다」** — 마커 형태가 어긋났거나 문자열 일부에만 넣었다.
  값 전체를 마커로 바꾸거나, 본문을 직접 보낸다.
- **「기준본 파일을 찾을 수 없습니다」** — 뒤진 경로가 가까운 곳부터 전부 함께 나온다.
  그 목록이 예상과 다르면 마커 문법이 아니라 **셸의 현재 작업 디렉토리**가 문제다
  (경로가 겹쳐 보이면 특히). 프로젝트 루트에서 다시 부른다.
  「건너뜀: …」이 붙은 줄이 있으면 사유대로 고친다 — `남이 쓸 수 있음` 이면 `chmod go-w`,
  `심볼릭 링크`·`내 소유가 아님` 이면 권한으로는 못 고치니 다른 경로를 쓰거나 `HANGUL_STAGING`
  을 지정한다.
- **「마커의 줄 범위가 파일을 벗어납니다」** — 파일의 총 줄 수가 함께 나온다. `grep -n` 으로 다시 센다.
- **「마커가 가리키는 기준본이 오래됐습니다」** — 6시간이 지난 파일이다.
  서버 본문이 바뀌었을 수 있으니 다시 fetch 하거나, 그대로 보낼 것이면 한 번 더 호출한다.

## 작업이 끝나면

기준본은 남겨도 되고 지워도 된다 (폴더 안 `.gitignore` 덕에 `git status` 에는 안 뜬다). 다만 **오래된 기준본이 남아 있으면** 새 문자열이 매칭되지 않아 에코 경로로 떨어지므로, 문서를 크게 바꿨으면 갱신한다.
